# Follow-up review: remaining presentation rough edges

The user requested a fresh, candid review after delivery. This review identifies remaining experience refinements from the current implementation; it does not treat the previous functional QA pass as proof of finished art direction.

## Evidence boundary

Source files were re-read in this review, with an independent second source review. The local route responds HTTP 200. A fresh browser capture could not be completed: in-app Browser was unavailable; Chrome extension tab discovery succeeded, but navigation, DOM access and capture timed out. No old screenshot has been relabeled as fresh evidence. This is a source-based follow-up review, not a completed new visual/browser audit or accessibility certification.

No landing code, source marketing copy, block structure or assets were changed during this review.

## Findings

1. **Hero media spacing is insufficiently responsive.** `ProductRecording.module.css` fixes the stage at 624px above 600px. `ProductRecording.tsx` defaults every width above 600px to the desktop recording. At a 768px viewport, a roughly 708px frame is about 459px tall, leaving roughly 165px of reserved stage height. This delays the media controls and weakens the relationship between available space and product scale. Proposed refinement: adapt stage sizing to viewport/media aspect ratio and evaluate a tablet-specific default; retain actual videos and controls.
2. **Quality comparison adds avoidable reading work.** `EditorialLanding.tsx` renders the original and translated passages inside separate scroll areas. CSS fixes their height at 266px on desktop and uses different RU/EN text sizes. The implementation does not synchronize passages. Readers must manually relocate corresponding text after scrolling. Proposed refinement: preserve every original word while making corresponding paragraphs easier to compare and providing clear access to the full excerpt; validate both desktop and stacked mobile behavior.
3. **Language interaction has little explanatory value.** Selecting a language only changes its oversized native name, English label and active button. It does not demonstrate a translation. Proposed refinement: use a deliberate static arrangement of the existing language names, or connect the interaction to genuine existing product evidence where available. Do not invent a sample or rewrite marketing text.
4. **The screenshot viewer reveals context more than detail.** `.dialogBody>img` fits the entire tall phone screenshot into 88svh, with no explicit zoom/pan control. For a 788×1705 source in a 900px-high viewport, displayed width is at most about 366px. This helps see the full screen but offers limited improvement for reading UI text. Proposed refinement: allow a larger readable image with scrolling/zoom while preserving the original screenshot.

These are refinement issues, not evidence that core functionality is broken. The suggested order is hero composition → comparison usefulness → screenshot inspection → language interaction. All proposals preserve existing copy, icon, product media and block order. A new live visual pass is still required before deciding final dimensions or declaring these refinements complete.
